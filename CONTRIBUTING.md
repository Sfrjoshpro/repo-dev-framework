# Contributing

Contributions should be small enough to review and explicit about what they change.

## Before coding

- open or select a task
- define its goal and boundaries
- identify required project knowledge
- record unresolved decisions

## Pull requests

A pull request should explain:

- what changed
- why the change was needed
- what was intentionally left out
- how the change was validated

Avoid mixing cleanup, refactors, and feature work unless they are inseparable.

## Documentation

Update long-lived design documentation only when design truth changes. Update `development-state/` when implementation truth changes.
